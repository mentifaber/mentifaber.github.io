why hybrid

RSA can't encrypt your message

A 4096-bit RSA-OAEP key can encrypt about 446 bytes. That's a sentence, not a document. So RSA never touches the message at all: it encrypts a key, and that key encrypts the message. CryptoVault does all of it for real, in your browser, with crypto.subtle; the ciphertext it prints is the actual output, not a stand-in.

the four steps

Inside CryptoVault

01

A fresh AES-256 key

A new random key for every message, used once, so a compromised message compromises nothing else.

02

AES-GCM for the payload

Fast, any size, and authenticated: tampering is caught on decrypt instead of quietly producing garbage.

03

RSA-OAEP for the key

256 bytes of key material, comfortably inside RSA's limit. It's the only thing the asymmetric layer ever sees.

04

One packet

The wrapped key, the IV and the ciphertext travel together; only the private key's holder can open it.

one file, zero trust in me

No dependencies: no npm tree, no CDN, no crypto library to audit. No network: open devtools and watch the network tab stay empty. No storage: keys live in memory for the tab's lifetime. Readable: one file you can scroll to the bottom of. That's the whole security argument, and it only works while it stays small.

honest scope

It doesn't distribute keys (the actual hard problem), doesn't prove who sent a message (that needs signatures), and served over a network it's only as trustworthy as whoever serves it. For anything that genuinely matters, use age or GPG. This is a working demonstration of the primitives, not audited infrastructure.

A crypto tool that overstates itself is worse than no tool.
