the problem

A pile, turned into a library

Manuals, alarm sheets, receipts, service notes, screenshots of things you meant to read later: they pile up in a Downloads folder where search means scrolling. DocCrawler turns that pile into a library you can search and question. The phone build runs in Termux with the internet off; the version below runs entirely in your browser.

how it works

Inside DocCrawler

01

Ingest

Every file is hashed with SHA-256 and de-duplicated. Add the same receipt twice and it's kept once.

02

Extract

Text straight from text and Markdown, pdf.js for PDFs, mammoth for Word, Tesseract OCR for photos of paper (each loaded only when needed).

03

Index

Ranked full-text search where a natural question is searched as any of its words, not a strict AND, so real questions find real answers.

04

Tag

Each document gets its top keywords as tags; add, remove or filter by your own.

05

The Librarian

Answers grounded in ranked excerpts with numbered citations. Turn the model off and it answers with plain retrieval, and nothing leaves the device.

06

Yours

The library lives in this browser's storage; export it as one file, import it anywhere.

the hard part (phone build)

Ollama has no Android build, so on the phone it runs inside a Debian container under proot-distro. Keeping it up took a run of fixes: a pkill that killed its own wrapper, a server that died with its launcher, a wrong HOME that made every model vanish, and timeouts long enough for a phone CPU to finish thinking.

the browser build

IndexedDB for the library, BM25 over passages for search, pdf.js, mammoth and Tesseract.js on demand, and Hive's free models for the Librarian when you allow it.

honest scope

Single-user on purpose. Auto-tags are a keyword heuristic, not a classifier; OCR is only as good as the photo. The Librarian cites its sources: check them for anything that matters.

The library stays on the device. The questions do too, if you want them to.
